# 중앙대학교 도메인 신청 준비 — Trauma Stress Lab

정보통신처 「온라인 신청 안내 매뉴얼(웹호스팅·도메인)」 기준으로, 이 저장소(`caupsynr`)가
운영 중인 홈페이지에 맞춰 정리한 신청 준비 문서.

---

## 0. 핵심 결론

1. **`psynr.cau.ac.kr`은 이미 발급되어 있다.** 현재 Wix(`td-ccm-neg-87-45.wixdns.net` /
   34.149.87.45)로 CNAME이 걸려 있고, 접속하면 **404**가 뜬다. 즉 신규 발급이 아니라
   **기존 도메인의 연결 대상 변경(재지정)** 신청이 맞다.
2. **교내 웹호스팅 신청은 필요 없다.** 정보통신처 호스팅은 Windows(ASP+MSSQL) 또는
   Linux(PHP+MySQL)만 제공한다. 이 사이트는 Python/Flask + gunicorn이라 교내 호스팅
   서버에 올릴 수 없다. → **도메인 신청서만** 제출한다.
3. **신청서의 "고정 IP" 항목은 협의가 필요하다.** 현재 서비스는 Render
   (`caupsynr.onrender.com` → 216.24.57.7 / 216.24.57.15)이고 인바운드 고정 IP가 없다.
   다만 **기존 psynr 레코드 자체가 외부(Wix) CNAME**이므로, 같은 방식(CNAME) 등록을
   요청할 선례가 이미 있다.
4. **첨부 점검표 2종이 모두 해당된다.** 취약점 점검표는 필수이고, 로그인 기능이 있어
   개인정보처리시스템 점검표도 대상이다. 제출 전 코드 보완 6건(§4) 처리 권장.

## 1. 신청 절차 (매뉴얼 → 우리 상황)

신청서 위치: **종합정보시스템 > 행정 > 정보통신처 > 신청서 관리**

| 매뉴얼 단계 | 우리 경우 |
|---|---|
| 웹호스팅 신청 | **해당 없음** — 교내 호스팅은 ASP/PHP만 지원, 우리는 Flask |
| 원격접속 계정(ARCON/VPN) 신청 | 해당 없음 — 교내 호스팅 서버 FTP 접속용 |
| 보안정책 등록 신청 | 해당 없음 — 교내(연구실) 서버가 아니라 외부 클라우드. 단, 향후 연구실 PC/서버로 옮기면 필수 |
| **도메인 신청** | **해당** — 아래 §2 값으로 작성 |

도메인 신청 화면 순서: ① 추가 → ② 사용자 정보 입력 → ③ 웹사이트명·도메인명 입력 →
④ 홈페이지 취약점 점검표 첨부(필수) → ⑤ 개인정보처리시스템 안전성 확보조치 관리실태
점검표 첨부(로그인 있으므로 해당) → ⑥ 개인정보 수집 동의 → ⑦ 저장 → ⑧ 승인요청

## 4. 점검표 대응 현황 (코드 근거)

### 이미 충족

| 항목 | 근거 |
|---|---|
| CSRF 방어 | `app.py:42` `CSRFProtect(app)` 전역 적용 |
| 비밀번호 안전 저장 | `app.py:593` `generate_password_hash(..., method='pbkdf2:sha256')` |
| 로그인 무차별 대입 완화 | `app.py:1228` `@limiter.limit("10 per minute", methods=["POST"])` |
| SQL 인젝션 | 전 쿼리 파라미터 바인딩(`?`), 문자열 보간은 내부 테이블명에만 사용 |
| 업로드 제한 | 확장자 화이트리스트(`app.py:54`), `secure_filename`, `MAX_CONTENT_LENGTH` 50MB |
| 접근통제 | `@login_required` + `_require_project_owner()` 프로젝트 소유권 검사 |
| 감사 기록 | `app.py:392` `audit()` — 행위/대상/전후값 기록 |
| 개인정보 최소수집 | 연구 참여자는 코드·성별·나이만 저장(가명처리), 이름·연락처 미저장 |
| 디버그 모드 | `app.py:3759` `app.run(debug=False)` |

### 신청 전 보완 권장

1. **SECRET_KEY 기본값 제거** — `app.py:38`에 `os.getenv("SECRET_KEY", "tsl-dev-secret-2025")`
   하드코딩 fallback이 있다. 미설정 시 기동 실패하도록 변경.
2. **세션 쿠키 플래그 미설정** — `SESSION_COOKIE_SECURE / HTTPONLY / SAMESITE` 설정 없음.
3. **보안 헤더 없음** — HSTS, `X-Content-Type-Options`, `X-Frame-Options`,
   `Referrer-Policy`, CSP 미적용.
4. **HTTPS 강제 없음** — HTTP 접근 시 HTTPS 리다이렉트 처리 없음.
5. **로그인 실패 처리** — rate limit이 `storage_uri="memory://"`라 인스턴스 재시작 시 초기화.
   계정 잠금·실패 로그 부재.
6. **dangling CNAME** — `psynr.cau.ac.kr`이 종료된 Wix로 남아 있어 서브도메인 탈취 위험.
   재지정으로 해소.

### 개인정보처리시스템 점검표에서 별도로 답해야 할 것

- 저장 위치: Supabase(외부 SaaS) — **처리위탁·국외 이전 여부**를 확인해 기재.
- 처리하는 개인정보: 연구자 계정(이메일 + 해시된 비밀번호), 문의 폼(`contact_messages`:
  이름·이메일·내용). 연구 참여자 데이터는 가명처리.
- 앱(Mind Mate)은 Google Apps Script → Google Sheets 전송 구조 — 홈페이지와 분리된
  처리 경로임을 명시.
